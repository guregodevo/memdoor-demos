- **Conflict characterization (verified on both samples):** A set is infeasible iff it contains a conflicting pair. Conflicts are: (1) same direction + properly crossing intervals (a_i<a_j<b_i<b_j or symmetric), (2) same start a_i=a_j (any direction, implies different b since (S,T) unique), (3) same end b_i=b_j (any direction, implies different a). Opposite-direction crossing is NOT a conflict (verified with explicit P-value assignment).
- **prev[j] computation:** prev[j] = max index i<j that conflicts with j. Endpoint conflicts (types 2,3) via single left-to-right pass with last_start[]/last_end[] arrays. Crossing conflicts (type 1) via CDQ divide-and-conquer on index, with sweep-line + segment tree on spatial dimension.
- **CDQ structure:** For each direction group, run two CDQ passes: Case A (sorted by a asc, query b-range) and Case B (sorted by b desc, query a-range). At each merge step, the sub-arrays are already sorted by the relevant key from recursive calls. Global segment tree reused with touch-and-clear pattern.
- **Segment tree:** Iterative, size 2*seg_size where seg_size = next power of 2 > N. Point update (set to max) with early termination. Range max query (standard iterative). Clear by setting leaf to 0 and updating ancestors with early termination.
- **Query answering:** Sparse table over prev[1..M]. Query [L,R]: if L>=R → Yes. Else check max(prev[L+1..R]) >= L → No, else Yes.
- **Performance concern:** 4 CDQ passes × O(M log M log N) ≈ 4 × 2×10^5 × 18 × 19 ≈ 2.7×10^8 operations. May be tight in CPython but should work in PyPy. Early termination in seg tree updates helps.
- **Key invariant:** |S_i - T_i| > 1 guarantees b-a >= 2, so query range (a_j+1, b_j-1) is never empty.
- **Verified samples manually:** Sample 1 query [2,4] has persons 2([1,3]) and 4([2,4]) crossing → No. Sample 2 query [1,6] has persons 1([1,5]) and 3([4,6]) crossing → No. All match expected outputs.
