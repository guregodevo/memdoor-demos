### NOTES

**Core Difficulty:** The pairing objective is max(X_a+X_b, Y_a+Y_b, Z_a+Z_b), a non-separable max-of-three-terms. A naive search over all pairings is exponential. The key structural reduction is: for each of the three coordinates, sorting by that coordinate in descending order and restricting to adjacent pairs captures an optimal solution. This reduces the problem to three instances of "select K non-adjacent elements from a line of N-1 values to maximize the sum," which is a classic maximum-weight-independent-set-on-a-path problem with a cardinality constraint.

**Why the three-sort reduction works (intuitive sketch):** For any optimal pairing, each pair has a "winning" coordinate (the one achieving the max). By an exchange/uncrossing argument, if we fix a coordinate c and sort by c descending, we can transform any crossing-free pairing into an adjacent-pair pairing without decreasing the total c-sum (by the rearrangement inequality, the c-sum of adjacent top-2K elements is maximal). Since the total max-price is at least the total c-sum for each c, and the max over the three sort orders recovers the true optimum, the reduction is valid. The samples confirm this (Sample 2's second case requires Y-sorting to achieve the answer 333).

**Why the heap-with-undo is correct for K non-adjacent selection:** This is the standard algorithm for maximum-weight independent set on a path with exactly K vertices. Popping the maximum vertex v and "absorbing" its neighbors into an undo-node (value = left + right − center) maintains the invariant that the remaining list encodes all viable continuations. Popping the undo-node later effectively "unselects" v and selects its two neighbors instead. This gives an exact greedy in O(K log N).

**Performance considerations:** Sum of N ≤ 10^5, so 3 sorts of ~10^5 elements plus 3 × 5×10^4 heap pops is very manageable in Python (well under 2 seconds with reasonable constant factors). The main risk is slow Python in the inner heap loop if we do attribute lookups or function calls repeatedly; using plain lists with local-variable caching avoids this.

### NEXT

- **Approach A (Plan's approach — primary):** For each of the three sort keys (X-desc, Y-desc, Z-desc): sort the N cakes, compute the N−1 adjacent-pair prices, then run the max-heap + doubly-linked-list + undo-node algorithm to select K non-adjacent values. Take the maximum over the three sort orders. Complexity O(N log N) per test case. Pitfalls: (1) boundary nodes (first/last in the linked list) have only one neighbor, so no undo-node is created; (2) stale heap entries (already-deleted nodes) must be skipped via a removed[] flag; (3) the undo value can be negative, which is fine (it represents a penalty for reverting a selection); (4) use a min-heap with negated values in Python; (5) cache list references in local variables inside the heap loop to avoid repeated global lookups.

- **Approach B (Aliens trick / Lagrangian relaxation):** For each sort order, instead of the heap-with-undo, binary-search on a per-selection penalty λ. For a fixed λ, the problem "select any number of non-adjacent elements maximizing (sum − λ·count)" is a simple forward DP in O(N). The count of selected elements is non-increasing in λ; binary-search for the λ that yields exactly K selections. The true answer is dp_value + λ·K. Complexity O(N log N · log V) per sort order where V ≈ 10^9 (so ~31 iterations). Pitfalls: (1) when the count "jumps" past K (no λ gives exactly K), need to handle the plateau by tracking the count at the boundary; (2) the DP must return both the max value AND the count of selected elements (tie-break toward more selections to make the count a step function); (3) larger constant factor and more complex code than Approach A.

- **Approach C (Simple DP, only feasible for small K):** For each sort order, run the DP dp[i][j] = max(dp[i−1][j], dp[i−2][j−1] + val[i]) in O(N·K). This is correct but O(N·K) = 5×10^9 for worst case — far too slow for the full constraints. However, it serves as a brute-force verifier for small N and K (e.g., N ≤ 200, K ≤ 100) to cross-check Approach A on random inputs. Pitfalls: (1) Python O(N·K) with N=10^5, K=5×10^4 is infeasible; (2) only useful as a testing oracle, not a submission strategy.

- **Approach D (Divide-and-conquer DP optimization):** The DP transition dp[i][j] = max(dp[i−1][j], dp[i−2][j−1] + val[i]) is a two-option recurrence, not a "range-max over k" form, so the standard D&C optimization (which requires quadrangle inequality on a cost(k,i) term) does NOT apply. This approach is infeasible and listed only to confirm it is a dead end.

- **Approach E (Try all 3 sort orders + all 3 tie-breakings per sort):** When multiple cakes share the same value of the primary sort key, their relative order is ambiguous. One could try all 3 secondary orderings (by the other two coordinates) for each primary sort, giving 9 total sortings. This hedges against any edge case where tie-breaking affects which adjacent pairs are formed. Complexity is 9× the base cost, still O(N log N). Pitfalls: (1) likely overkill — the max-function symmetry probably makes tie-breaking irrelevant; (2) increases runtime by 3×; (3) still worth implementing as a safety check if the primary approach fails hidden tests.

- **Recommended priority:** Implement Approach A first (it is the intended solution, fastest, and handles all constraints). Use Approach C as a brute-force checker on small random inputs during development. If any hidden test fails, investigate whether tie-breaking (Approach E) is the issue, then consider Approach B as an alternative core algorithm.
