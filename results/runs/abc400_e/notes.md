- **Key insight:** A 400 number is N = p^(2a)·q^(2b) where p, q are distinct primes, a≥1, b≥1. Since N ≤ 10^12, we need p·q ≤ 10^6, so both primes are ≤ 10^6.
- **Sieve:** Bytearray-based sieve up to 10^6 is fast (< 0.1s). Returns list of ~78498 primes.
- **Enumeration:** For each pair (p,q) with p<q and p²q² ≤ 10^12, loop a from 1 while p^(2a)·q² ≤ 10^12, and inner loop b from 1 while p^(2a)·q^(2b) ≤ 10^12. Early breaks keep it tight. Total 400 numbers generated is on the order of a few hundred thousand.
- **No duplicates possible:** By unique factorization with p<q fixed, each (p,q,a,b) gives a unique value. set() is just a safety net.
- **Query answering:** bisect_right on sorted list gives O(log M) per query. M ~ 200K-400K, so log M ~ 18-19. 200K queries → ~4M comparisons, trivial.
- **Sample verification:** 400=2⁴·5², 36=2²·3², 10^12=2^12·5^12, 123454321=41²·271². All correctly generated by the enumeration.
- **Performance:** Sieve ~0.05s, enumeration ~1-2s (dominated by inner loops for small primes), query answering ~0.2s. Total well under 5s.
- **Edge case A=36:** Smallest 400 number is 36=2²·3². bisect_right correctly returns index of 36.
- **Optimization note:** The `p2 * 9 > LIMIT` check (smallest q²=9) prunes the outer loop early. The `p2*q2 > LIMIT` check in the inner loop breaks as soon as q is too large.
