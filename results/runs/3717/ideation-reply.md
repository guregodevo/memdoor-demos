### NOTES

The problem has two clearly separable sub-problems. The first is computing, for every window of size x in the array (there are n - x + 1 of them), the minimum number of ±1 operations to make all elements in that window equal. The minimum is achieved by setting all elements to the median of the window, and the cost is the sum of absolute deviations from the median. The second sub-problem is selecting exactly k non-overlapping windows from these candidates to minimize total cost, which is a classic weighted interval scheduling / DP problem.

The core difficulty lies in computing all n - x + 1 window costs efficiently. Naively sorting each window takes O(x log x) per window, giving O(n x log x) total, which can be as bad as O(n² log n) when x is around n/2. The constraints (n up to 10^5) demand something closer to O(n log x) or O(n log n). The DP selection step is straightforward once costs are known: it is O(n k) and since k ≤ 15, it is fast regardless.

Key subtleties: (1) The sliding-median maintenance must handle deletions of elements leaving the window, which is non-trivial with heaps (requires lazy deletion and rebalancing). (2) The DP must correctly enforce the non-overlap constraint: if a window starts at index i, the previous window must start at index at most i - x. (3) Values can be negative, but this does not affect the median-based cost formula. (4) When x is even, any value between the two middle sorted elements is optimal; picking either gives the same total absolute deviation.

### NEXT

- **Approach A – Two-heap sliding median + 2-D DP:** Maintain a max-heap (left) and min-heap (right) with lazy deletion to track the median of the current x-window in O(log x) per slide, alongside running sums of each half to compute the absolute-deviation cost in O(1) per window. Then run the DP: dp[i][j] = min(dp[i-1][j], dp[i-x][j-1] + cost[i-x]) for i from x to n, j from 1 to k. Space O(n k) ≈ 1.5M entries, time O(n log x + n k). Pitfalls: lazy-deletion bookkeeping (marking removed indices, cleaning heap tops), rebalancing after each insert-and-delete pair, off-by-one in which index the cost array refers to (start vs. end of window).

- **Approach B – Fenwick-tree (BIT) sliding median + DP:** Coordinate-compress all nums values. Maintain a BIT over counts and a BIT over sums. For each window, the median is found by binary search on the count-BIT (find the value where cumulative count ≥ (x+1)//2), and the cost is computed as (median * count_left - sum_left) + (sum_right - median * count_right), all in O(log n) with the binary search giving O(log² n) per window. Same DP on top. Pitfalls: coordinate compression must handle all distinct values; the sum-BIT stores value × count so updates are O(log n) but with potentially large values; the binary search on the BIT for the "k-th order statistic" must be implemented carefully.

- **Approach C – Sorted list with bisect (simpler median) + DP:** For each window, maintain a Python list kept sorted (using bisect.insort and list.remove). Median is list[x//2]. Cost is computed by iterating or by maintaining a running sum. Insertion and removal are O(x) each due to list shifting, giving O(n x) total for all windows. With n, x up to 10^5 this is O(10^10) worst case – too slow. However, if the hidden tests have moderate x (say ≤ 1000), this passes easily. Pitfalls: O(x) per update makes it infeasible for large x; list.remove is O(x) and must match the exact value (watch for duplicates).

- **Approach D – Prefix-min DP formulation (alternative DP state):** Define f(j, i) = minimum total cost to place j windows where the j-th (last) window starts at index i. Then f(j, i) = cost[i] + min(f(j-1, s)) for all s ≤ i - x. Precompute a running prefix-min array for each layer j-1 so the lookup is O(1). Iterate j from 1 to k, i from 0 to n-x. Answer is min(f(k, i)) over valid i. This avoids the 2-D dp[i][j] table and uses O(n) space per layer. Pitfalls: initial layer j=1 is just f(1, i) = cost[i]; the prefix-min must be over the *previous* layer's values, not updated in-place; need to guard that s ≥ 0.

- **Approach E – Segment-tree / sorted-multiset via "treap" or "skiplist" for median:** Implement a balanced BST (treap or randomized BST) supporting insert, delete, rank (k-th smallest), and sum-of-first-k. Each window slide is two operations (insert new, delete old) plus a rank query, all O(log x). Cost derived from sums stored in the BST. Same O(n k) DP on top. Pitfalls: implementing a correct randomized BST with subtree sums in Python is error-prone and slower than heaps due to constant factors; recursion depth for treap split/merge could hit Python's limit for x up to 10^5.

- **Approach F – "Cost precomputation via two passes" (no explicit median structure):** For each window, note that sum of |a_i - m| where m is the median can be computed if we know the median and the sum of elements below and above it. We can find the median by selection in O(x) per window (quickselect) and compute the cost in O(x), giving O(n x) total. Same issue as Approach C – feasible only for small x. Pitfalls: quickselect has O(x) average but O(x²) worst case per window (mitigate with median-of-medians or randomization); still O(n x) overall.
